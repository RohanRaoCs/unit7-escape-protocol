How it works

UNIT-7 combines six AI techniques, and each one has a specific job. This page explains what each technique does, why it is there, and where you can see it working in the simulator. Everything is written in Python 3 using only the standard library; the website runs the same Python package in the browser with Pyodide.

The mission

The facility is a 31 × 21 grid generated from a seed: a maze with extra loops and a few open rooms. UNIT-7 starts in the top-left corner. To escape it must collect three keycards (it chooses the order), reach the terminal and work out the vault code from the clues there, then reach the exit while that code is still valid. A run fails if the hull reaches zero or 900 ticks pass.

Architecture

Every tick, the world updates, the sensors measure the drone's distance across the map, the fuzzy system turns that into a threat level, and the behaviour tree decides what to do. Navigation actions call A*; the lock action calls the CSP solver.

A* search

Plans every route the agent walks.

escape_room/search.py

See it replan

What it does. Finds the cheapest route from the agent to its current goal. The heuristic is the Manhattan distance; it never overestimates (each step costs at least 1), so A* always returns an optimal route while exploring far fewer cells than Dijkstra.

Cost of a step. 1 on clean floor, 6 on coolant, plus a penalty near the drone that grows with the fuzzy threat level. Routes bend away from danger in proportion to how dangerous it is.

Planning in time as well as space. Laser gates follow a known timetable (on for 4 ticks out of every 10). With space-time planning, a state is "this cell at this point in the timetable", and waiting is allowed. A* can therefore plan to pause for one tick and walk through a gate as it switches off, instead of taking a long detour.

Noticing change. Every tick, the remaining route is checked. A new plan is made when rubble blocks it, when a gate would fire, when the agent has been pushed off it, or when the threat along it has risen more than 20% since it was planned.

Choosing the keycard order. All 3! = 6 orders are scored with breadth-first distances, and the shortest tour (agent → three keycards → terminal) wins.

Constraint satisfaction

Cracks the vault lock.

escape_room/csp.py

See the lock change

The puzzle. Five dials D1 to D5, each a digit from 0 to 9, all different. The clues are constraints such as "D2 + D4 = 11", "D3 > D5", "D1 is odd" or a checksum.

Making fair puzzles. The generator adds random true clues until exactly one code fits, then removes every clue it can without losing uniqueness. Each puzzle is therefore minimal: no clue is redundant.

Four solvers to compare.

  • Plain backtracking: try values in order and undo on conflict.
  • Forward checking: after each choice, remove values that can no longer work from the other dials.
  • MRV: fill the dial with the fewest remaining options first.
  • AC-3: make every pair of dials consistent before searching at all.

Together these cut the search from about 1,850 assignments to about 8. In the simulator, dialling in the code takes one tick per four assignments, so a better solver means a faster escape.

When the constraints change. A power surge rewires two dials: clues that no longer hold are removed and new ones are added. The agent's known code stops working, and it must solve the new puzzle.

Behaviour tree

Decides what to do next.

escape_room/bt.py, agent.py

See it decide

The tree, in priority order:

  • Survive: if the threat is high, evade the drone.
  • Escape: if the vault is unlocked, go to the exit.
  • Crack the lock: if all keycards are held, go to the terminal and solve the lock.
  • Collect keycards: plan the best tour and go to the next keycard.
  • Hold position: if no route currently exists, wait.

Why a tree. It is evaluated from the top every tick, so Survive interrupts anything below it the moment danger appears, and the agent picks up its task again once the danger has passed. A power surge needs no special code: "Vault unlocked?" simply fails and the tree falls through to "Crack the lock".

Fuzzy logic

Judges how dangerous the drone is.

escape_room/fuzzy.py

See it react

Why fuzzy. "Close", "alert" and "badly damaged" do not have sharp boundaries. A drone 4 cells away is somewhat near and somewhat medium-distance. Fuzzy logic lets the agent reason with those partial memberships instead of hard thresholds.

Inputs.

  • Distance to the drone, measured along corridors, so walls give cover.
  • How alert the drone is, taken from its state machine.
  • The agent's hull integrity.

Rules. Nine rules map these inputs to a threat level, for example "IF distance is Near AND the drone is Alert THEN threat is Very High" and "IF distance is Medium AND integrity is Critical THEN threat is Medium". A damaged agent is therefore more careful.

Output. A threat score from 0 to 100 (Mamdani inference, centroid defuzzification). It raises A* step costs near the drone, and above 68 it makes the behaviour tree switch to evasion.

Finite state machine

Controls the adversary.

escape_room/drone.py

See the drone

The security drone has four states:

  • Patrol between waypoints until it sees the agent (within its range, with a clear line of sight).
  • Alert: investigate the spot where it last saw the agent.
  • Chase, if it still sees the agent, until it loses sight for 6 ticks or its 30-tick battery runs out.
  • Cooldown for 12 ticks, then back to Patrol.

Contact costs the agent 25% of its hull and stuns it for 2 ticks.

Q-learning

A learning agent to compare against.

escape_room/qlearn.py

Open the lab

What it learns. A table of values Q(cell, keycards held, move), filled in by trial and error with ε-greedy exploration. After a few hundred episodes, following the best value from each cell gives an escape that is at or near the shortest possible.

Why it is not UNIT-7's controller. A learned table describes the map it was trained on. When rubble falls on its route, the policy walks straight into it until it has been retrained, whereas A* finds a new route in a few milliseconds. The lab demonstrates this directly.

Where the code is

One Python package drives the desktop app (python main.py), the tests (python -m unittest), the evaluation (python evaluate.py) and this website.
